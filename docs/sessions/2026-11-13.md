## Audit findings

- Yahoo returns each roster player as
  `[[metadata fragments], {"selected_position": [{"coverage_type": "date", ...},
  {"position": "IL"}, {"is_flex": 0}]}]`. The generic extractor dropped the
  sibling block and `_roster_position` could not parse fragment lists, so
  `rosters.roster_position` was NULL for 165/165 persisted rows. The earlier
  test used a synthetic flat payload.
- NULL slots were treated as non-injury, so the roster always looked full.
  The optimizer always evaluated ADD × DROP pairs, the UI preselected the
  first roster player as the drop, and the direct injury-slot league rule was
  display-only.
- Stale capacity evidence produced success-shaped HOLD; lineup coverage
  counted O/NA players; impact without a drop silently used the best measured
  drop; team needs were a single sentence.
- The running API and frontend images (built 2026-11-13 16:54/16:57 UTC)
  match commit `93fd50f` by source hashes and bundle content, so Source
  Integrity & Coverage is deployed despite documentation saying otherwise.
