## Fix (local, not deployed)

- **Admission module:** `backend/app/features/waivers/admission.py` and
  `router.py`.
  - One heavy read at a time.
  - The slot is resolved before any database dependency, so queued reads hold
    no connection.
  - Disconnected clients (queued or loading) are cancelled and logged
    `status=499`, with a `queue` timing phase.
- **Regression tests:** four new tests in `tests/test_waivers.py` failed on
  the deployed code, then passed. They cover an abandoned read finishing,
  three overlapping reads with three sessions, a queued read that kept going,
  and a real PostgreSQL query that kept running.
- **Validation:**

  - Frontend (unchanged): unit 63/63, `tsc -b`, and the production build with
    `VITE_LIVE_DRAFT_POLL_INTERVAL_MS=60000` is byte-identical to the
    deployed `index-0LZfF9Tl.js`.
  - Repository Playwright desktop 22/22 (mobile not run).
- **Unchanged:** scoring, weights, samples, status, availability, capacity,
  optimizer, horizons, exact pair, invariant and model version.
